# Luquora Launcher v0.2：模组与整合包

日期：2026-11-16

状态：用户已于 2026-11-16 确认本设计，进入实施。文末验收要求不是已通过的结果。

## 1. 意图与已确认方向

将现有 Windows Minecraft Java 启动器扩展为可以日常使用的模组与整合包启动器。主要参考 HMCL 的安装流程、Prism 的实例与资源管理方式，保留 LQL 现有银灰与石墨界面风格。参考功能与交互，不复制其他启动器代码、品牌或资源。

用户已确认的功能路线：创建 Fabric / Forge / NeoForge / Quilt 实例 → 搜索安装模组和必要依赖 → 下载或导入整合包 → 启动游戏 → 管理和更新已安装内容。补齐任务进度、取消、失败重试和更新前备份。

首个资源平台为 Modrinth。CurseForge 为后续接入项，需要项目自有 API Key 及平台准入与下载政策核实；v0.2 不提供伪造的 CurseForge 入口，不声称支持其在线内容或本地 manifest 包。

## 2. 方案与决定

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 在现有 Electron / Vue / TypeScript 与独立实例基础上扩展，先打通 Modrinth | 复用现有账号、Java、下载、进程和日志；需要扩展实例数据与版本解析 | 用户已选择此方向 |
| 第一轮同时接入 Modrinth、CurseForge 及其他整合包平台 | 内容覆盖更广，但外部凭据、下载限制和格式差异扩大首轮验证范围 | 后续阶段 |
| 替换启动器技术栈或复制成熟启动器应用层 | 丢弃现有能力，增加迁移及许可边界问题 | 不采用 |

以下实现细节是实现者提案，不追溯为用户已逐项确认的决定。

## 3. 平台、约束与非目标

- 支持 Windows 10/11 x64；沿用 Electron、Vue 3、TypeScript、Naive UI、npm 和 XMCL 核心库。
- 原版实例、账号、本地角色、设置、日志和现有用户数据必须保持可用。微软游戏服务准入仍按现有事实记录，不把本轮工作当作认证问题已解决。
- 一实例只能有一种通用加载器；不提供 Forge + Fabric 混装，不承诺自动修复所有模组冲突。
- 不扩展到皮肤编辑、联机服务、服务器托管、云同步、插件系统、自动更新服务、主题编辑器或游戏根目录迁移。
- 不承诺四种加载器支持所有历史与未来版本；只展示来源明确支持的组合，公布实测组合与失败限制。
- 不自动提交、推送、创建分支或对外发布。使用临时验收数据，不操作用户已有游戏存档。

## 4. 用户流程与界面

沿用现有导航和视觉样式，新增“资源中心”与“下载任务”，为实例增加“内容管理”入口。

### 创建与安装实例

1. 选择游戏正式版、原版或加载器、加载器版本，填写名称。
2. 加载器列表按该游戏版本查询，默认选择稳定或推荐版本并允许调整；无兼容版本时明确提示。
3. 显示将安装的游戏、加载器和 Java；提交后进入任务视图。
4. 安装、校验完成后才能启动；失败或取消保留可重用的完整文件，支持重试。

已有原版实例继续按原逻辑启动。为避免在已有存档上无意切换环境，本轮加载器选择只发生在新实例创建及整合包创建，不直接改造已安装实例的加载器。

### 资源中心

- 分类：模组、整合包、资源包、光影。支持搜索、分页、游戏版本筛选；模组和整合包支持加载器筛选。
- 详情显示名称、作者、介绍、许可、平台链接、版本、兼容环境及依赖。远程介绍以文本或经过严格净化的 Markdown 呈现，不运行远程 HTML 或脚本。
- 模组、资源包、光影安装前选择目标实例和具体兼容版本。整合包安装创建独立新实例。
- 默认稳定发布；测试版可显式选择。切换筛选或搜索后，旧请求结果不能覆盖新结果。
- 无结果、加载中、断网、限流、版本不兼容分别显示可理解的状态；外部链接仅允许预期 HTTPS 站点并由系统浏览器打开。
- 下载光影不等于安装渲染支持；页面提示需要兼容的光影加载模组，不暗中安装未经确认的图形环境。

### 实例内容管理

- 分别列出 mods、resourcepacks、shaderpacks；支持安装本地文件、查看来源、版本和更新状态。
- 模组启用/禁用通过受管文件重命名实现，不删除；移除文件进入回收站，失败保留记录和文件。
- 本地导入文件不要求必须属于 Modrinth；能按摘要匹配则补充来源，不能匹配则标为“本地文件，兼容性未验证”，不伪造项目或版本信息。
- 资源包和光影安装只放入对应目录，不自动改写游戏 options.txt 或模组配置。
- 运行中、启动检查中或实例有写任务时禁止修改内容。更新预览列出新增、替换、移除和依赖，再由用户执行。

## 5. 版本、加载器与启动

实例记录区分 Minecraft 基础版本、加载器类型/版本、实际启动版本 ID。Java 要求取基础版本及加载器的已核实要求，不把派生版本 ID 当作 Mojang manifest ID。

- Fabric 与 Quilt 从各自官方元数据查询版本并取得客户端 profile。
- Forge 与 NeoForge 从各自官方分发/Maven 来源解析版本及安装器，执行官方定义的客户端安装步骤；不得用改 mainClass 或仅下载 installer.jar 冒充安装完成。
- 优先复用已安装 XMCL 的适用接口。当前依赖的 Fabric、Forge、Quilt 入口已查到；NeoForge 支持及当前 Forge 安装器兼容性必须先做可行性验证，不能根据名称相近直接视为可用。
- 加载器安装器及处理器只来自已核实官方来源；进程采用参数数组、无 shell、隐藏终端、超时及取消等待。进程退出之前不允许复用或清理其工作目录。
- 派生描述的继承链、依赖、主类、启动参数与库均参与解析和校验；加载器生成文件不强行要求存在官方客户端 JAR 式的 SHA-1。
- 共享原版资源保持可复用；加载器元数据及生成产物按完整版本组合隔离，避免不同实例覆盖相同派生 ID。
- 修复操作校验原版与加载器文件，不覆盖实例的模组、配置和存档。

## 6. Modrinth 与依赖安装

通过主进程封装 Modrinth API；设置明确的 LQL User-Agent、请求超时、响应尺寸限制和有限重试，遵守限流。公开资源读取不要求用户登录，不引入独立后端。

- 以项目/版本 ID 与文件摘要记录来源；下载使用平台提供的实际文件名、尺寸和摘要，主进程重新验证兼容性与路径。
- 多文件版本优先选平台 primary 文件；缺失且无法唯一确定时要求用户选择，不能一次安装所有平台构建。
- 递归解析 required 依赖，尊重指定 version_id；仅给 project_id 的依赖按目标游戏、加载器和客户端环境选兼容版本。
- optional 与 embedded 不自动当作必需文件下载；incompatible 依赖与已安装受管项目冲突时拒绝执行并指出项目。
- 用已访问集合处理重复与循环，用上限防止异常依赖图。固定版本依赖不兼容、缺失或项目无客户端版本时，整个计划失败，不能静默跳过。
- 安装前展示主资源和将新增的必要依赖；同项目已存在不同版本时展示替换。不能根据文件名推断两个不同来源文件可以安全覆盖。
- SHA-512 和 SHA-1 按元数据支持；不得改写或伪造摘要以适配现有 SHA-1 下载器。

## 7. 整合包安装与导入

本轮格式为 Modrinth `.mrpack`，包括资源中心在线安装与系统文件对话框导入。普通 ZIP 只在确认为同一格式时接收，不把任意文件夹或 CurseForge manifest 当作已支持格式。

1. 有界读取 ZIP 与根目录 modrinth.index.json，校验 formatVersion、game、依赖、文件列表、摘要、尺寸、环境和下载地址。
2. 提取基础游戏与单一加载器要求；未知必需依赖、多加载器、来源不支持的游戏组合显示明确错误。
3. 显示包名、版本、游戏、加载器、文件数量及可选客户端文件，用户确认名称与可选内容后安装。
4. 跳过 client=unsupported 文件；required 必装，optional 默认不选。缺少 env 按格式定义处理。
5. 在未公开的受管临时实例中安装基础游戏、加载器和文件，再应用 overrides 与 client-overrides；不应用 server-overrides。客户端覆盖同路径文件时以后者为准。
6. 完整校验并保存包清单后，将实例正式登记并选中；失败或取消不留下显示为就绪的半成品实例。已验证下载缓存可以保留复用。

ZIP 处理拒绝路径穿越、绝对路径、盘符/UNC、NTFS 数据流、链接、Windows 保留名、重复/大小写冲突条目及越界目标。限制条目数量、单文件与总展开大小；具体上限写入实施计划并以测试固定。覆盖目录只能写入实例 game 子目录，不能覆盖启动器设置、令牌或加载器共享数据。

包内下载地址和重定向按 Modrinth 官方格式的允许来源规则检查，不将不受信任包的任意 URL 交给下载器；私有网络地址、本机地址和非 HTTPS 地址拒绝。

## 8. 更新、备份与恢复

### 单个资源

先检查兼容新版本，再生成包含依赖的更新计划。下载与校验在临时区完成；变更前备份将替换/移除的文件及资源清单。落盘失败恢复旧文件与清单；用户改动的文件不静默覆盖，要求先处理冲突。

更新保留模组启用/禁用状态，不启用此前禁用的模组。本地未知来源文件不自动更新、删除或推断冲突。

### 整合包

在线安装保存项目 ID 与版本 ID，用于检查包更新。本地导入保存包版本和清单，可用新的本地 .mrpack 更新；无法确认在线来源时不伪造自动更新能力。

更新使用旧包清单、新包清单和当前文件进行三方比较：

- 原包管理文件未被用户改动，可替换或移除。
- 用户新增文件保留；包内同名新文件与之冲突时阻止更新，展示冲突路径。
- 用户修改/删除的包管理文件若新包也改变同一路径，阻止更新并展示冲突；用户单独修改而新包未改变时保留用户状态。
- saves、screenshots、logs、crash-reports 始终保留，不从新包覆盖或从旧包清单移除；包覆盖试图写入这些目录时拒绝。
- 更新前备份全部将变更的文件、旧清单、实例元数据与旧加载器启动标识；不以复制整个共享目录代替备份。
- 跨游戏/加载器组合更新先安装新组合，验证成功后再切换实例元数据；失败仍保留旧组合可用性。

变更使用持久化事务记录：重启先恢复未完成事务，恢复前锁定该实例，避免混合版本被启动。提供最近一次更新的恢复入口；恢复会检测更新后的用户修改，存在冲突则阻止自动恢复，不丢弃新存档或用户内容。备份占用及清理入口可见，不无限静默积累。

## 9. 数据、任务与边界

- 原配置读取时增加有验证的迁移，写前备份原配置；旧原版实例缺少 loader 字段时解释为原版。不因升级把合法旧数据当作配置损坏。
- 实例增加加载器、来源与资源清单；内容清单保存在实例元数据区域，不扫描、修改受管目录外的文件。
- 业务 IPC 继续使用有限方法、类型契约及主进程输入校验。renderer 不传任意目标路径、命令或安装 URL；本地文件必须经系统对话框选择。
- 安装、资源修改、整合包更新共享一个写任务协调入口，本轮同一时间执行一个写任务；并行下载仍有限。等待中的任务可取消，执行中可取消，失败可重试；重启不自动恢复网络传输，只恢复事务并允许重试。
- 任务状态包含类型、实例、阶段、已完成/总量、失败原因；总量未知时显示阶段，不编造百分比。取消等待所有文件写入与子进程结束。
- 应用关闭沿用现有确认流程并覆盖新任务。新任务与游戏启动、内容修改和实例删除互斥检查发生在主进程。
- 原始请求错误、包介绍、URL 和日志不得泄露账号令牌；不上传日志或收集遥测。

## 10. 验收与完成定义

| 层级 | 必须证明的行为 |
| --- | --- |
| 迁移和回归 | 原版实例、角色、账号、启动设置保留；现有自动化检查通过；升级后可读原配置 |
| 加载器 | 四种加载器分别有一组来源支持的正式版组合，真实安装并进入游戏主菜单；显示正确加载器环境并正常退出 |
| 资源 | 使用真实 Modrinth 搜索/版本接口；真实安装至少一个含 required 依赖的客户端模组，验证文件摘要与独立实例隔离 |
| 内容管理 | 启用/禁用重启保留；本地导入与未知来源可管理；运行中修改被拒绝；资源包和光影进入正确目录 |
| 整合包 | 至少一个有明确版本的真实包完成在线安装、本地导入并进入主菜单；client/server 环境、覆盖优先级与可选文件有自动化用例 |
| 更新和恢复 | 资源更新保留禁用状态；包更新保留用户配置与存档；冲突阻止写入；失败及模拟进程中断后恢复旧一致状态 |
| 异常与边界 | 错误摘要、网络失败、取消、限流、恶意 ZIP、路径逃逸、损坏清单、依赖循环、缺失依赖与不兼容版本均有针对性用例 |
| UI 与打包 | 实际 Electron 窗口完成搜索、版本选择、安装、取消、失败重试及更新预览；960×640 和常用缩放可用；Windows 构建与打包检查通过 |

真实网络结果、模拟边界测试、真实游戏主菜单和打包后运行分开记录。Node 单测通过不代表安装器兼容，生成 JAR 不代表模组已加载，进程存在不代表进入主菜单。遇外部条件阻塞时精确记录未验收项，不将其计为完成。

## 11. 实施前核实项

1. 对固定依赖中的 Forge / Quilt 与 NeoForge 支持做最小实测；必要新增依赖先检查实际发布接口、许可及 Electron 兼容性。
2. 核实 Modrinth API、.mrpack 格式的当前字段、下载来源与 User-Agent 要求，形成固定异常测试样本。
3. 在实施计划中确定四种加载器的实测版本组合和真实整合包样本，不将某一天的 latest 写为长期兼容承诺。
4. 所有真实下载与启动使用隔离验收目录；界面截图不含微软授权信息。
