# Luquora Launcher v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Windows 上交付支持微软账号、原版安装、自动 Java、独立实例和真实启动的 Luquora Launcher 首版。

**Architecture:** 一个 Electron 工程，Vue renderer 通过受限 preload 调用主进程业务服务。主进程拥有认证、文件、下载与游戏子进程；JSON 保存设置与实例，独立加密缓存保存会话。先验证已发布核心库和真实认证，再实现安装、启动及完整交互。

**Tech Stack:** Electron、Vue 3、TypeScript、electron-vite、npm、XMCL core/installer/user、MSAL Node、Vitest、Playwright Electron、electron-builder NSIS。

**Spec:** [已确认的 v0.1 设计](../specs/2026-11-13-lql-v0.1-design.md)。执行者必须同时阅读设计与本计划。

## Global Constraints

- 产品名称为 **Luquora Launcher**，缩写 **LQL**。
- 技术路线为 **Electron + Vue 3 + TypeScript**。
- 正式支持 Windows 10/11、x64。Windows 7/8、32 位、ARM64 和其他桌面系统不列入 v0.1 验收。
- 首轮兼容性验收固定为 **1.16.5、1.20.1、26.3**。
- 首版仅提供原版正式版安装，不提供快照、预发布版、远古版本入口。
- 使用 LQL 自己的微软应用标识。不得使用示例中、XMCL、Prism 或其他启动器的应用标识和 API 密钥。
- 公共桌面客户端不保存应用 client secret。
- 首版同一时间只执行一个安装任务；同一时间只允许一个游戏进程。
- 首版将实例专属目录移入 Windows 回收站，成功后再删除元数据；回收站操作失败就保留实例并报告，不自动改成永久删除。
- 不自动提交、推送、创建分支或发布安装包到外部平台；本计划没有自动 commit 步骤。
- 本地已有 Node v24.16.0、npm 11.13.0；系统 JDK 候选位于 `C:\Develop\JDK`，游戏 Java 不能以开发机 Java 代替自动配置验收。
- 真实 Microsoft 登录、主菜单和安装后运行必须保留真实证据；模拟测试和构建成功不能替代。

## Review Focus

1. 用户在终止/下载回调尚未完成时关闭窗口：不能继续写已删除目录或留下虚假的完成状态；Task 5、6、7 覆盖。
2. 应用崩溃后旧 PID 被其他程序复用：不能误杀；残留游戏可识别时保护实例；Task 6 覆盖。
3. 实例目录被 junction/符号链接替换，或目标使用相似路径前缀：不能越界读写、解压或删除；Task 2、4、5 覆盖。
4. HTTP 错误体/游戏分块输出意外回显凭据：不能因为日志入口不同或秘密跨块而漏脱敏；Task 3、6 覆盖。
5. 打包环境中的 ESM 依赖、资源路径和安全存储不同于开发环境：必须先通过 Electron 探针，再在实际安装产物复验；Task 1、3、8 覆盖。

## 执行约定与依赖图

按 Task 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 顺序实施。任务共享接口多，建议由当前会话逐项实施，完成后集中独立审阅；不为每个文件启动代理。

每项逻辑任务遵循：先写失败用例 → 确认失败由目标行为缺失导致 → 最小实现 → 运行指定测试。工具初始化和纯视觉样式不增加镜像实现的测试。

若无自有 client ID 或测试账号，只完成认证的本地实现与测试，记录真实登录未验收；继续其他本地任务。不得为此复用上游 client ID、伪造会话或把账号检查降级为离线启动。进入真实验收时提供准确的用户操作步骤，不收集用户密码。

## Task 2: 配置、实例存储和安全 IPC

**Files:** 创建 `src/shared/contracts.ts`、`src/main/storage/*.ts`、`src/main/ipc.ts`；修改 main/preload；测试 `tests/storage/{store,paths,instances}.test.ts`、`tests/e2e/ipc.spec.ts`。

**Interfaces:** 在 `contracts.ts` 定义下列跨任务共享形状，所有序列化时间为 ISO 字符串：

```typescript
type LaunchSettings = { memoryMiB: number; width: number; height: number; fullscreen: boolean; javaPath: string | null };
type Instance = { id: string; name: string; versionId: string; createdAt: string; installation: 'incomplete' | 'ready'; overrides: Partial<LaunchSettings> };
type AccountSummary = { id: string; name: string; uuid: string; status: 'ready' | 'reauth-required' };
type AppConfig = { schemaVersion: 1; gameRoot: string; selectedInstanceId: string | null; selectedAccountId: string | null; defaults: LaunchSettings; instances: Instance[] };
type ErrorCode = 'NETWORK' | 'AUTH_CANCELLED' | 'AUTH_EXPIRED' | 'AUTH_REQUIRED' | 'NO_ENTITLEMENT' | 'NO_PROFILE' | 'DISK_FULL' | 'NOT_WRITABLE' | 'INTEGRITY' | 'JAVA_MISSING' | 'JAVA_INCOMPATIBLE' | 'SPAWN' | 'GAME_EXIT' | 'INVALID_INPUT' | 'BUSY' | 'CONFIG_CORRUPT' | 'SERVICE';
type AppError = { code: ErrorCode; stage: string; message: string; nextAction: string };
type InstallProgress = { instanceId: string; stage: 'metadata' | 'java' | 'files' | 'verify' | 'complete'; completed: number; total: number | null; unit: 'bytes' | 'files' };
type GameStatus = { instanceId: string | null; phase: 'idle' | 'checking' | 'starting' | 'running' | 'exited' | 'failed'; exitCode: number | null; userStopped: boolean };
type AppSnapshot = { config: AppConfig; accounts: AccountSummary[]; installation: InstallProgress | null; game: GameStatus };
type VersionSummary = { id: string; releasedAt: string };
```

主进程 `loadConfig(userData: string): Promise<AppConfig>`、`saveConfig(userData: string, config: AppConfig): Promise<void>`；`assertManagedPath(root: string, candidate: string): Promise<string>` 返回验证后的绝对路径。存储服务 `createInstance(name: string, versionId: string): Promise<Instance>`、`updateInstance(id: string, patch: { name?: string; overrides?: Partial<LaunchSettings> }): Promise<Instance>`、`removeInstance(id: string): Promise<void>`。

preload 暴露 `window.lql`：`getSnapshot()`、`listVersions()`、`createInstance(name, versionId)`、`updateInstance(id, patch)`、`removeInstance(id)`、`selectInstance(id: string | null)`、`selectAccount(id: string | null)`、`saveSettings(defaults: LaunchSettings)`、`chooseGameRoot()`、`chooseJavaPath(instanceId: string | null)`、`openInstanceFolder(id)`、`addAccount()`、`cancelAuth()`、`removeAccount(id)`、`installInstance(id)`、`cancelInstall()`、`launchInstance(id)`、`stopGame(force: boolean)`、`readLog(sessionId: string)`、`exportLog(sessionId: string)`、`onEvent(listener)`。普通业务命令返回 `Promise<void>`，创建/修改返回实例，选择路径通过主进程对话框完成，日志读取返回 `Promise<string[]>`，导出返回 `Promise<string | null>`；`onEvent` 同步返回取消订阅函数。认证和安装命令只确认任务被接纳，不等待整段交互完成。

事件使用可判别联合：`snapshot` 携带 `AppSnapshot`、`auth-code` 携带 `{ code, verificationUri, expiresAt }`、`auth-ended` 携带 `{ outcome: 'success' | 'cancelled' | 'failed' }`、`error` 携带 `AppError`、`log-lines` 携带 `{ sessionId, lines: string[] }`。未来任务分别定义主进程内部类型，不把令牌加入这些共享类型。

- [ ] 写失败测试：原子写失败保留原配置；损坏 JSON 保留原件并返回 `CONFIG_CORRUPT`；相似前缀/`..`/junction/目标父目录被替换拒绝越界；实例改名不移动目录；回收站失败不删记录。
- [ ] 运行 `npm test -- tests/storage`，确认失败来自缺失行为；实现 schema 校验、串行写入、路径实路径校验、生成 ID、配置恢复提示、回收站删除和选中项回退。
- [ ] 实现默认目录 `%APPDATA%\LuquoraLauncher`；首次运行默认最大内存为物理内存 25% 取整到 256 MiB，限制在 1024～4096 MiB；宽高 1280×720、窗口模式、Java 自动选择。内存输入允许 256 MiB～物理内存 80%，分辨率每边 320～16384；无法满足设备边界时给出明确错误。只有未创建实例时可选新游戏根目录。
- [ ] 编写 IPC 集成失败用例并实现输入校验：错误 ID、非法枚举、越界设置、恶意路径、非应用窗口发送者均被拒绝；安全对话框产生路径，renderer 不获得任意路径操作接口。设置 CSP、导航拦截和受控 HTTPS 浏览器打开；不暴露原始 IPC。
- [ ] 运行 `npm test -- tests/storage`、`npm run test:e2e -- tests/e2e/ipc.spec.ts`、`npm run typecheck`，全部通过；安全存储中无令牌字段。

**可交付结果：** 可持久化且路径受限的实例管理与业务桥接，不依赖认证服务在线。
